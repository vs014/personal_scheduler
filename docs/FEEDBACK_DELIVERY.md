# 앱에서 Codex로 피드백 보내기 — 구현 조사

2026-10-25 · 조사 당시 기록. 0.2.5에서 공식 CLI 전송 기능을 구현했다. 최신 구현·검증 상태는 DEVELOPMENT.md의 0.2.5 절을 참조한다. 실계정 생성 검증은 아직 필요하다.

## 결론

공식 Codex CLI의 `codex cloud exec`를 여백 백엔드에서 실행하여 새 클라우드 검토 작업을 생성하는 경로를 추천한다.
현재 열린 Codex 대화에 메시지를 직접 추가하는 공개 인터페이스는 이번 조사에서 확인하지 못했다.
새 작업에는 저장소·버전·선택 피드백·개발 기록을 전달하여 맥락을 이어간다. 기존 대화 전체가 자동 계승되지는 않는다.

## 확인한 근거

- 공식 저장소 https://github.com/openai/codex
- 클라우드 명령 정의 https://github.com/openai/codex/blob/main/codex-rs/cloud-tasks/src/cli.rs
- 작업 제출 구현 https://github.com/openai/codex/blob/main/codex-rs/cloud-tasks/src/lib.rs
- SDK https://github.com/openai/codex/tree/main/sdk/typescript
- App Server https://github.com/openai/codex/tree/main/codex-rs/app-server

npm에 배포된 @openai/codex 0.164.0으로 다음 도움말을 실제 실행했다:
`codex cloud --help`, `codex cloud exec --help`, `codex login --help`.
exec / status / list / diff / apply 명령을 확인했다. cloud는 EXPERIMENTAL로 표시된다.
공식 소스에서 exec가 로그인된 ChatGPT 계정과 환경을 사용하고, 표준입력의 프롬프트로
새 작업을 만들고 URL을 출력하는 것을 확인했다. 로그인 없이 도움말만 실행했으며
사용자 피드백을 외부로 전송하거나 작업을 생성하지 않았다.
문서 사이트 일부는 이 환경에서 연결되지 않아 공식 GitHub 소스와 배포 CLI를 교차 확인했다.

## 추천 사용자 흐름

1. 최초 한 번 Codex 공식 로그인과 개발 환경/저장소 선택. 여백 일정 AI 로그인과 별도이다.
2. 사용 중 피드백 작성 → 개발 AI에게 보내기 → 전송 내용 확인.
3. 앱이 로컬 전송 대기열에 저장하고 CLI를 백그라운드 실행한다.
4. 작업 ID/링크를 수신한 경우에만 ‘접수 확인’ 표시. 상태 조회로 검토 중/완료/실패를 표시한다.
5. 검토 결과는 작업 열기로 확인한다. 앱 내 답변 가져오기는 지원 출력 형식·사용자 계정으로 별도 검증한다.
6. 개선 작업은 별도 브랜치/검토 가능한 변경으로 이어간다. 접수 성공을 앱 수정·설치 완료로 표시하지 않는다.

## 구현 항목

- Windows용 공식 CLI를 고정 버전 및 검증된 배포 파일로 준비한다. 비공개 HTTP API를 재구현하지 않는다.
- 로그인/연결 점검/환경·브랜치 설정 UI와 인증된 로컬 서버 엔드포인트를 추가한다.
- 선택된 피드백 스냅샷, 앱 버전, 요청 ID, 전송 상태, 원격 task ID/URL을 SQLite에 저장한다.
- subprocess 인자 배열과 stdin으로 JSON 자료를 전달한다. shell=True나 문자열 명령 조합을 사용하지 않는다.
- 요청 ID·원격 작업 ID를 기록해 중복 클릭을 막는다. 네트워크 단절로 생성 여부가 불명확하면
  무조건 재전송하지 않고 ‘접수 확인 필요’로 남겨 작업 목록과 대조한다. 원격 멱등성은 확인되지 않았다.
- 선택한 피드백만 전송한다. DB, 일정 전체, 토큰/로그인 주소는 첨부하지 않는다.
- 계정의 Codex 사용량·한도를 따른다. API 키 과금 경로로 자동 전환하지 않는다.
- 검토 작업에는 피드백을 자료로 취급하고 사용자 요청 범위에서 분석·개선안을 기록하도록 지시한다.
- 전송 큐는 앱 재시작 후 복원한다. PC가 꺼진 동안 새 전송은 하지 않지만 접수된 클라우드 작업은
  로컬 프로세스와 별개로 실행되는 경로다. 실제 동작·완료 확인은 계정 테스트로 검증한다.

## 선행 조건과 남은 검증

현재 체크아웃에는 앱 코드가 아직 Git에 커밋되지 않았고 HEAD는 Initial commit이다.
새 클라우드 작업이 최신 앱 코드를 얻도록 저장소/브랜치 반영과 환경 연결을 먼저 완료해야 한다.
원격 Git 상태를 추정하지 않으며 실제 대상 브랜치의 코드 버전을 확인한다.

사용자 Windows에서 공식 Codex 로그인, 환경 접근 권한, 최소 피드백 1건의 작업 생성/상태 조회,
사용 한도, 실패 재시도, 한국어/장문 입력, 프로세스 출력 형식·로그 비노출을 확인해야 한다.
CLI가 실험적이므로 버전을 고정하고 변경 시 통합 검사를 수행한다.

## 대안

Codex SDK는 로컬 CLI를 감싸며 startThread/run/runStreamed/resumeThread를 지원한다.
앱 안에서 개발 대화를 계속하고 답변을 표시하기에 적합하지만 해당 실행 호스트와 코드가 필요하다.
SDK의 로컬 thread 재개를 기존 클라우드 대화 재개와 동일하게 취급하면 안 된다.
현재 클라우드 개발 흐름에는 cloud exec 경로를 먼저 적용하고, 지속적인 앱 내 대화가 필요할 때
SDK/App Server 통합을 별도로 검증한다.
