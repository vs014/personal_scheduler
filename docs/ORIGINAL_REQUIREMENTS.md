# Codex 개발 시작 프롬프트 — 개인 생활 AI 비서

작성 기준: 2026-10-25
이 문서 전체를 Codex에 전달한다. 구현 완료 보고서가 아니라 개발 지시서다.

## 1. 역할과 목표

너는 이 프로젝트를 설계하고 구현하는 개발자다. 아래 사용자 요구를 바탕으로 실제 실행·저장·수정·동기화가 가능한 개인 생활 AI 비서를 개발하라. 화면 목업만 만들고 완료했다고 보고하지 말 것.

대중에게 판매하거나 공개하지 않고 사용자 한 명만 사용한다. 개인 편의성, 사용자만의 판단 알고리즘, 지속적인 기능 확장이 최우선이다. 경쟁 앱과의 독창성 경쟁이나 다중 사용자 협업 기능은 목표가 아니다.

## 2. 사용자 피드백 — 확정된 요구

1. 휴대폰과 노트북에서 같은 일정·할 일·개인 정보를 관리하고 동기화한다.
2. AI와 대화하면 일정과 할 일을 추출하고 등록·수정·조회·완료를 도와준다.
3. 부족한 정보는 선택지 버튼으로 우선 확인한다. 자유 입력은 보조 수단이다. 불필요한 질문을 반복하지 않는다.
4. 일정 겹침, 이동 시간 부족, 중요한 과제의 집중에 대해 조언한다. 사용자가 최종 변경을 결정한다.
5. 개인 백데이터를 관리한다. 주요 장소, 직업·근무 형태, 가족·지인과의 관계, 생활 패턴, 선호 등을 필요한 범위에서 이용한다.
6. 개인 백데이터는 한눈에 보기 쉬워야 하며 사용자가 확인·수정·삭제할 수 있어야 한다. 추측을 사실로 저장하지 않는다.
7. 한국어로 사용한다. 사용자 의미 데이터와 화면 문구는 한글 중심으로 저장·표시한다.
8. 외부 달력 앱 연동이 아니라 자체 캘린더를 만든다. 항목을 누르면 자세한 설명을 볼 수 있어야 한다.
9. 날짜·시간이 정해지지 않은 일정과 할 일도 관리한다. 모든 항목에 날짜 입력을 강요하지 않는다.
10. 휴대폰 푸시 알림과 앱 내부 알림을 모두 지원한다.
11. 운영 비용은 무료 우선이다. 이미 결제 중인 ChatGPT Pro 구독을 활용할 수 있는지 검증한다. 추가 과금이나 유료 가입을 임의로 진행하지 않는다.
12. 외부 AI와 클라우드 저장은 허용한다. 그렇다고 모든 개인정보를 모든 요청에 전송해도 된다는 뜻은 아니다.
13. 설명은 결론과 최우선 내용부터 짧게 제공한다. 자세한 설명은 펼쳐 보기로 제공한다.

아래 예시는 기능 검증용이지 실제 사용자 할 일의 등록 지시가 아니다.
- 쿠팡에서 섬유유연제 사기
- SK브로드밴드 계약 호실 수정하기
- 침대 구매하기

## 3. 착수 전 검증: ChatGPT 구독과 앱 실행 비용

개발 도구로 Codex를 쓰는 것과 완성된 앱에서 AI를 호출하는 것을 구분한다.

2026-10-25에 확인한 공식 안내의 요지는 다음과 같다.
- ChatGPT 플랜으로 Codex를 사용할 수 있고 사용량 제한이 적용된다. [O1]
- 일반 OpenAI API 계정의 사용료는 ChatGPT 구독과 별도다. [O2]
- 공식 Sign in with ChatGPT에는 지원되는 앱에서 구독 사용량을 이용하는 경로가 있다. 공개 문서는 오픈소스·로컬 호스팅 앱을 설명하며 원격 호스팅 등의 적용 조건을 구분한다. 지원되는 자체 호스팅 VM 경로도 별도 문서가 있다. [O3–O5]
- 이 로그인만으로 사용자의 기존 ChatGPT 대화나 메모리에 접근하는 것은 아니다. [O3, O4]

구현 전에 위 공식 문서를 다시 읽고, 비공개 개인 앱의 실제 실행 위치와 사용 계정에 적용되는 조건을 확인하라. 임의의 모델명이나 비공개 API를 가정하지 않는다.

첫 검증은 최소한의 텍스트 요청으로 진행한다. 공식 인증, 해당 계정의 사용 가능 모델, 구독 사용량 차감 방식, 연결 가능한 실행 환경을 확인하고 성공·미검증·불가를 구분해 기록한다. ChatGPT 로그인 비밀번호, 브라우저 쿠키, 세션 토큰을 추출하는 우회 구현은 금지한다.

추가 비용 없는 공식 연결이 검증되면 해당 경로를 기본 AI 연결로 구현한다. 검증되지 않았다면 구독만으로 앱 AI가 무료라고 주장하지 말고, 기본 데이터 관리 기능과 규칙 기반 기능을 먼저 구현한다. 이때 AI 미연결 상태를 명확히 표시하고 자유로운 AI 대화까지 완성했다고 보고하지 않는다. 유료 API로 자동 전환하지 않는다.

노트북을 AI 실행 호스트로 삼으면 꺼져 있을 때 AI 요청을 처리할 수 없다는 제약을 명시한다. 앱의 데이터 관리와 예약 알림을 AI 호스트에 불필요하게 종속시키지 않는다. 서버·DB·푸시·지도 서비스의 무료 한도와 중단 조건도 따로 검증한다. 무료 상시 운영을 검증 없이 보장하지 않는다.

## 4. 추천 기본안: 일정과 할 일을 구분해서 함께 관리

이 절의 세부 화면 이름과 분류는 개발 기본안이며 사용자가 수정할 수 있게 한다.

### 4.1 일정

약속처럼 특정 시점이나 기간을 차지하는 항목이다. 제목, 설명, 날짜, 시작·종료 시각, 장소, 참석 관계자, 중요도, 알림을 관리한다.

시간 정보는 다음을 구분한다.
- 날짜와 시간이 확정됨: 캘린더 시간 칸에 표시.
- 날짜만 확정되고 시간은 미정: 그 날짜의 ‘시간 미정’ 영역에 표시. 종일 일정과 구분.
- 실제 종일 일정: 종일 영역에 표시.
- 날짜도 미정: 별도 ‘미정 일정’ 목록에 보관.

모르는 시각을 00:00이나 임의의 한 시간으로 채우지 않는다. 종료 시각이나 소요 시간이 없으면 정확한 충돌·이동 검토가 불가능할 수 있음을 표시한다.

### 4.2 할 일

날짜·시간 없이도 저장할 수 있는 실행 항목이다. 최소 입력은 제목 하나다. 설명, 카테고리, 중요도, 예상 소요 시간, 하위 작업, 참고 링크, 선택적 마감일·알림을 추가할 수 있다.

기본 진행 상태는 ‘미시작 / 진행중 / 완료’다. ‘대기중 / 나중에’는 진행 상태와 별개인 관리 표시로 두어 답변 대기와 완료를 혼동하지 않는다.

다음 네 정보는 서로 독립시킨다.
- 실제 마감일: 반드시 끝내야 하는 기한.
- 실행 계획일: 사용자가 처리하기로 고른 날.
- 알림 시각: 다시 알려줄 시각.
- 실행 시간 블록: 실제로 시간을 확보한 경우에만 생성.

마감일 없는 항목을 오래되었다는 이유만으로 ‘기한 초과’ 처리하지 않는다. 실행 계획을 미루어도 실제 마감일은 바뀌지 않는다.

### 4.3 추천 목록 구성

- 받은함: 떠오른 항목을 제목만으로 빠르게 저장.
- 전체 할 일: 모든 미완료 할 일. 구매·생활 행정·집안일·기타 등의 분류 및 검색.
- 오늘 할 일: 오늘 처리할 항목만 선택해 보는 화면. 원본의 복사본을 만들지 않는다.
- 대기·나중에: 답변을 기다리거나 당장 하지 않을 항목.
- 완료 기록: 완료 이력 확인 및 완료 취소.

‘오늘 할 일’로 선택해도 실제 마감일이나 예약 시간이 자동 생성되지 않는다. 다음 날에는 미완료 원본을 유지하고 다시 추천할 수 있지만, 임의의 마감일 연체로 표시하지 않는다.

예시 동작:
- ‘쿠팡에서 섬유유연제 사기’: 날짜 없이 저장하고 사용자가 ‘오늘 할 일’에 추가 가능.
- ‘SK브로드밴드 계약 호실 수정하기’: 설명·연락 메모를 남기고 연락 후 답변 대기 표시 가능. 실제 고객센터 운영시간은 확인 없이 만들어 넣지 않는다.
- ‘침대 구매하기’: ‘설치 공간 측정 / 제품 비교 / 구매’ 등의 하위 작업을 제안하고 사용자 승인 후 추가.

### 4.4 자체 캘린더와 연결

PC에서는 캘린더 옆에 할 일 목록을 둔다. 모바일에서는 캘린더와 목록을 탭 또는 접을 수 있는 패널로 전환한다.

날짜 없는 항목을 달력으로 끌거나 ‘계획에 넣기’ 버튼을 누르면 ‘그날 하기 / 시간 정하기’를 선택하게 한다. ‘마감일 설정’은 별도 동작이다. 할 일 자체는 유지하고 계획만 연결한다. 달력에서 시간 블록을 지워도 원래 할 일이 삭제되지 않아야 한다.

## 5. 대화와 선택지

처리 흐름:
사용자 입력 → 일정·할 일·개인정보 후보 추출 → 필요한 정보만 선택지로 확인 → 일정 검토 → 저장 내용 확인 → 서버 저장 → 결과 표시.

- 한 문장에서 여러 항목을 추출할 수 있다.
- ‘주말’, ‘저녁’, ‘나중에’처럼 모호한 표현은 설정 또는 선택지로 해결한다.
- 선택지에는 상황에 맞게 ‘미정 / 직접 입력 / 건너뛰기’를 제공한다.
- 단순 할 일의 날짜나 장소는 필수가 아니다. 없는 날짜를 얻으려고 질문을 계속하지 않는다.
- ‘내일로 미뤄줘’의 대상이 여러 개면 항목 선택지를 제공한다.
- 변경 전후를 보여 주고 승인받는다. 완료·간단한 등록 등 명시적인 한 번의 클릭은 그 자체를 승인으로 처리해 중복 확인을 줄인다.
- 저장에 성공하기 전에는 ‘저장했어요’라고 말하지 않는다.
- AI의 제안은 구조화된 데이터로 검증한 뒤 서버에서 처리한다. AI가 DB를 직접 임의 수정하게 하지 않는다.
- ‘약속 잡아줘’는 MVP에서 앱 내부의 일정 작성·관리를 뜻한다. 상대방 연락, 외부 예약 확정, 구매·결제는 하지 않는다.

## 6. 나만의 알고리즘

자연어 이해·설명과 실제 판단 규칙을 분리한다. 초기 버전은 규칙과 확인된 데이터로 계산하고 AI가 짧게 설명하게 한다. 근거 없는 점수나 사용자의 심리·체력을 단정하지 않는다.

### 시간 충돌
확정된 일정 구간의 겹침을 검사한다. 날짜만 있는 항목을 종일 점유로 간주하지 않는다. 시간 블록이 없는 할 일은 약속 충돌과 별개로 다룬다.

### 이동 가능성
‘다음 일정 시작 - 이전 일정 종료’와 ‘이동 시간 + 사용자 여유 시간’을 비교한다. 인접한 앞뒤 일정 모두 검토한다.

이동수단과 출발·도착 정보가 충분할 때만 계산한다. 지도 API를 연결하지 못하면 사용자가 입력한 이동 시간이나 확인된 과거 값을 사용하고 근거를 표시한다. 실제 교통정보를 조회하지 않았는데 실시간 예상 시간인 것처럼 말하지 않는다.

### 일정·할 일 부담
예상 작업 시간, 실제 확보된 시간, 중요도, 마감일과 사용자가 설정한 여유 시간을 검토한다. 중요 항목이 두 개라는 사실만으로 ‘불가능’이라고 판단하지 않는다. 예상 소요 시간이 없으면 선택지로 요청하거나 정밀 평가를 보류한다.

### 오늘 할 일 추천
사용자의 명시적 중요도·마감일·예상 시간·가능한 시간대·대기 여부를 이용해 소수의 항목을 제안한다. 초기 추천 개수는 3개로 설정하되 사용자가 변경할 수 있게 한다. ‘왜 추천했는지’를 한 문장으로 제공한다.

알림을 안 읽거나 일을 오래 미뤘다는 이유로 중요도를 무한히 높이지 않는다. ‘유지 / 오늘 하기 / 나중에 / 삭제’를 선택할 수 있게 한다. 사용자의 거절 이유는 확인 후 반영한다.

### 조언의 최종 형식
짧은 근거 → ‘그대로 유지 / 시간 변경 / 다른 날 보기’ 선택지. 자동으로 사용자의 일정을 옮기지 않는다.

## 7. 개인 백데이터

‘기본 정보 / 주요 장소 / 가족·지인 / 생활 패턴 / 비서 설정’으로 나누고 목록과 편집 카드를 제공한다.

각 정보에는 항목명·값·출처·확인 여부·최근 수정 시각을 저장한다. 대화에서 얻은 새 정보는 ‘확인할 정보’에 제안하고 승인 후 확정한다. 기존 정보와 충돌하면 이전 값과 새 값을 비교해 선택하게 한다. 삭제한 값을 과거 대화로부터 자동 복구하지 않는다.

나이보다 출생연도가 관리에 적합할 수 있지만 필수 수집하지 않는다. 가족의 정확한 주소 등 민감한 정보는 실제로 필요한 때에만 요청하고, 지역 수준 정보로 충분하면 더 자세한 정보를 요구하지 않는다.

기존 ChatGPT 대화·메모리는 자동으로 가져올 수 있다고 가정하지 않는다. 앱 자체 대화 또는 사용자가 직접 제공한 자료만 입력 출처로 삼고, 가져오기 화면에서 선택·확인한다.

한국어 정책: 사용자 의미 데이터인 제목·설명·분류·상태·개인정보 항목명·메모·조언은 한글 중심으로 저장하고 표시한다. 고유명사와 원문은 의미를 훼손하지 않는다. 코드 식별자, UUID, URL, 시간대 ID, 표준 날짜 값 같은 기계 처리용 항목은 표준 형식을 쓰고 사용자 화면과 내보내기에 한글 의미를 매핑한다. 이는 유지보수를 위한 기술적 기본안이다.

## 8. 알림과 신뢰성

- 휴대폰 푸시와 앱 내부 알림함을 제공한다. 권한 거부·미설정·구독 만료 상태를 숨기지 않는다.
- PWA를 선택하면 실제 iPhone과 PC에서 설치·알림 지원 조건을 공식 문서와 실기기로 확인한다.
- 앱이 열려 있을 때만 돌아가는 타이머를 예약 알림 시스템으로 쓰지 않는다.
- 알림 예약은 DB에 저장하고 서버 작업이 처리한다. AI 요청 성공 여부와 분리한다.
- 완료·삭제·일정 변경 시 기존 알림을 취소하거나 갱신한다. 발송 직전에도 최신 상태를 확인한다.
- 중복 방지 키, 실패 재시도, 방해금지 시간, 미루기·중지 기능을 둔다.
- 날짜 없는 할 일도 마감일 없이 알림만 설정할 수 있다.
- 주간 점검이나 일일 브리핑은 사용자가 켠 경우에만 보내며, 알림 시각은 설정에서 선택한다. 기본적으로 수십 건의 개별 독촉을 보내지 않는다.
- 서버의 발송 시도와 기기의 실제 수신을 구분하고 수신을 무조건 보장하지 않는다.

## 9. 구조와 보안

개인용으로 유지보수하기 쉬운 단일 애플리케이션을 기본안으로 삼되 다음 모듈의 경계를 분리하라.

화면 / 일정·할 일 / 대화·선택지 / 개인 백데이터 / 판단 규칙 / AI 제공자 연결 / 알림 / 영속 저장.

AI 제공자, 지도 제공자, 저장소를 인터페이스 뒤에 두어 나중에 교체할 수 있게 한다. 처음부터 마이크로서비스나 불필요한 복잡한 인프라를 도입하지 않는다.

일정, 할 일, 실행 계획, 알림, 개인 정보, 변경 이력을 구분해 저장한다. 날짜만 있는 값과 정확한 시각을 구분하며 기본 시간대는 Asia/Seoul로 한다. 기술적으로 정확한 시각은 표준 시간 정보로 저장하되 한국 시간으로 표시한다.

한 명만 사용하는 앱이어도 인증과 서버 측 소유권 검증을 한다. 공개 회원가입은 막고 명시적으로 허용한 사용자만 접근 가능하게 한다. 비밀키·인증 토큰을 프런트엔드 코드나 저장소에 넣지 않는다. 개인정보와 토큰을 불필요하게 로그에 남기지 않는다.

다른 기기의 변경 충돌, 네트워크 실패, 중복 등록을 처리한다. 데이터 내보내기·가져오기와 삭제를 제공한다. 가져오기는 미리보기·중복 검사를 거치고 저장 결과를 알린다.

기술과 호스팅은 무료 한도, 상시 알림 실행 가능성, 접근 제어, 데이터 이전 가능성을 검증해 선택한다. 유료 기능이나 한도를 넘는 기능은 사용자 동의 없이 활성화하지 않는다. 무료 한도 도달 시 자동 과금하지 않고 해당 기능을 안전하게 제한한다.

## 10. MVP 범위와 검증

MVP에 포함:
- 실제 저장·수정·완료 가능한 일정과 날짜 없는 할 일.
- 자체 캘린더, 오늘 할 일, 상세 패널.
- 대화형 추출과 선택지 기반 확인. AI 연결이 검증된 환경에서 실제 요청 테스트.
- 기본 충돌·부담 분석. 이동 시간은 확인 가능한 데이터가 있는 범위에서 구현.
- 개인 백데이터 확인·수정·삭제.
- 휴대폰·PC 동기화, 푸시 및 내부 알림.

후순위:
복잡한 반복 규칙, 음성 입력, 영수증·이미지 인식, 자동 이메일 분석, 위치 추적, 패턴 학습, 외부 캘린더 동기화. 구매·결제·외부 예약 대행은 제외한다. 후순위 기능을 위해 데이터 구조를 막히게 만들지는 않는다.

필수 테스트:
1. 예시 세 가지 할 일이 날짜 질문 없이 등록되며 새로고침 후 유지된다.
2. ‘오늘 하기’ 선택과 해제가 실제 마감일을 변경하지 않는다.
3. 날짜만 있는 항목, 시간 확정 항목, 종일 항목, 날짜 미정 항목이 구분된다.
4. 할 일을 시간 블록에 연결한 뒤 블록만 삭제해도 할 일은 남는다.
5. 복수 항목 추출·모호한 날짜·선택지·취소·완료 취소가 처리된다.
6. 새 개인정보가 승인 전 확정되지 않고, 수정·삭제가 추천에 반영된다.
7. 앞뒤 일정 충돌과 이동 시간 부족이 재현되며, 자료가 없으면 불확실성을 표시한다.
8. 완료한 할 일의 예정 알림이 취소되고 중복 발송을 방지한다.
9. 휴대폰·PC 사이 변경이 동기화되고 권한 없는 접근은 거부된다.
10. AI 연결 실패·사용량 한도·무료 인프라 한도에서도 기존 데이터가 유지되고 유료 호출로 몰래 전환하지 않는다.

## 11. Codex의 실행 순서와 보고 형식

1. 현재 저장소를 확인하고 기존 파일을 불필요하게 삭제하지 않는다.
2. 무료 운영과 공식 AI 연결의 전제부터 확인하고 가능한 구성 및 제약을 짧게 제시한다.
3. 데이터 모델과 기본 저장·화면부터 실행 가능한 작은 단위로 구현한다.
4. AI 연결, 선택지, 판단 규칙, 개인 정보 관리, 알림을 순차 통합한다.
5. 테스트를 실행하고 실제 실행한 검증과 미실행 검증을 구분한다.
6. README에 실행 방법, 필요한 설정, 모바일 접근·푸시 조건, 무료 한도, 백업·복구, 알려진 제한을 기록한다.

매 보고는 ‘이번에 구현한 핵심 / 실행 방법 / 남은 제약’ 위주로 짧게 한다. 추가 질문이 꼭 필요하면 되도록 2~4개 선택지와 추천안을 제공한다. 이미 정해진 요구를 다시 묻지 않는다. 실제 인증·배포·기기 테스트를 수행하지 않았으면 완료했다고 말하지 않는다.
