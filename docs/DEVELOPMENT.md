# 여백 · 개발용 상세 기록

현재 버전: **0.2.6** · 작성일: 2026-10-25 · 대화 등록 구현, 실제 ChatGPT 계정 연결·추론은 미검증

아래 초기 설계·검증은 0.1.0 당시 기록입니다. 최신 변경은 마지막의 **0.2.4 — 2026-10-25 내보낸 피드백 반영**을 참조하세요.

## 요구사항과 이번 범위

원문은 저장소의 `docs/ORIGINAL_REQUIREMENTS.md`에 보관한다. 앱에서 [원본 요구사항 내려받기](/api/docs-download/original)도 가능하다. 사용자가 추가한 확정 요구:

- 모든 화면에서 질문·기능 피드백을 남기는 상시 진입점.
- 대화를 보관하고 개선 요청을 이후 업데이트까지 추적.
- 사용자용 한 장과 개발용 상세 기록을 언제든 열람.

첫 구현 범위는 일정·할 일의 영속 저장, 캘린더, 인증, 피드백 대화·상태·전달, 두 문서 열람이다.
원문 MVP 전체를 완료했다고 간주하지 않는다. 자동 AI 연결/응답, 개발 에이전트 자동 호출,
푸시, 개인 백데이터, 이동·부담 분석, 반복 일정, 복수 시간 블록, 데이터 가져오기는 후속 개발이다.

## 구조와 선택 이유

- React + TypeScript + Vite: 한국어 반응형 화면. 별도 UI CDN이나 외부 폰트 요청 없음.
- FastAPI: 화면과 같은 출처의 JSON API. 단일 애플리케이션으로 운영.
- SQLite: Python 표준 라이브러리, 파일 기반 영속 저장. 별도 DB 구독·서버 불필요.
- `backend/models.py`: 입력·상태·날짜 규칙 검증.
- `backend/storage.py`: 스키마, 연결, 비밀번호 해시.
- `backend/guide.py`: 명시적인 정적 도움말. 생성형 AI라고 표시하지 않음.
- `backend/app.py`: 세션·일정·피드백·내보내기·문서 API.
- `backend/feedback.py`: 개발자가 로컬 DB의 피드백에 답변·상태 기록.
- `web/src`: 화면, 대화창, 캘린더, 앱 문서.
- `docs`: 저장소와 앱이 함께 사용하는 문서 원본. 배포 버전과 함께 갱신.

## 데이터와 신뢰성

`items`는 할 일·일정의 제목, 설명, 상태, 관리 표시, 중요도, 실행 계획일, 실제 마감일,
시간 구분, 시작·종료 시각, 장소를 보관한다. 날짜 미정은 null이며 00:00을 채워 넣지 않는다.
시각은 현재 단일 날짜의 한국 현지 시·분으로 해석한다. 실제 알림 도입 때 timezone-aware
순간값으로 변환하는 별도 처리가 필요하다. 생성·수정 이력의 시각은 UTC ISO 형식이다.

첫 버전은 항목당 실행 계획 하나를 지원한다. UI의 ‘실행 계획 해제’는 계획 날짜·시간만
지우며 할 일과 마감일을 보존한다. 여러 실행 시간 블록을 분리 저장하는 확장은 후속 과제다.
확정된 시작·종료 시간이 모두 있는 항목끼리 화면에서 단순 겹침을 안내한다. 종료 미정·
날짜 미정·종일 항목의 정밀 겹침, 이동·부담 분석을 수행했다고 표시하지 않는다.

`threads`, `messages`, `history`에 질문·오류·제안, 대화, 처리 이력을 저장한다.
피드백 저장과 최초 안내 응답은 한 DB 트랜잭션으로 처리한다. 요청 식별자로 중복 등록을
방지한다. 동일 식별자에 다른 내용을 보내면 충돌을 반환한다. 수정·삭제는 revision을
검사하여 오래된 화면이 최신 내용을 덮어쓰지 못하게 한다.

화면은 15초마다, 다시 포커스를 받을 때 서버의 최신 상태를 읽는다. 같은 서버에 접속한
기기는 같은 데이터를 읽는 구조다. 실제 휴대폰 간 동기화는 아직 검증하지 않았다.
오프라인 쓰기는 지원하지 않는다. 실패한 입력은 열린 폼에 유지하고 성공 전 완료 문구를
표시하지 않는다. 앱 종료·새로고침 전 저장하지 않은 초안은 보존하지 않는다.

## 인증과 개인정보

- 1인 소유자만 지원. 최초 비밀번호는 12자 이상이며 로컬 접근에서만 설정한다.
- scrypt 해시와 개별 salt 저장; 세션은 무작위 토큰의 SHA-256 해시만 저장.
- HTTP-only, SameSite=Strict 쿠키. HTTPS origin 구성 시 Secure 적용.
- 모든 개인 데이터·문서·내보내기 API는 로그인 필수.
- 변경 요청의 custom header와 Origin 검사, Host 제한, API no-store, CSP 적용.
- 로그인 실패 10회 후 해당 클라이언트 IP를 15분 제한.
- 비밀번호나 입력 원문을 오류 응답·접근 로그에 넣지 않음. 운영 스크립트는 access log 비활성화.
- 피드백에 현재 화면 이름만 선택적으로 첨부. 일정·화면 캡처·다른 개인정보 자동 첨부 없음.
- 내보내기는 선택한 피드백의 대화 전체와 이력만 포함; 다운로드 전 미리보기.
- 서버의 DB와 백업은 개인정보다. `.data/`와 SQLite 파일은 Git 제외, 외부 공유 금지.

인터넷 공개 전에 반드시 로컬 최초 설정, HTTPS, 허용 origin, 서버 접근 제어,
백업·복구를 검증한다. 로컬 프록시가 외부 트래픽을 전달하는 경우에도 초기 설정을
외부에 노출하기 전에 마쳐야 한다. 현재 클라우드 작업 환경은 사용자용 상시 배포가 아니다.

## 피드백에서 업데이트까지

1. 사용자가 앱에서 피드백과 추가 대화를 저장한다.
2. 필요한 대화만 선택하여 JSON 전달 파일의 내용을 확인한다.
3. 사용자가 Codex에 파일을 첨부한다. 다운로드는 전송을 의미하지 않는다.
4. 개발자가 자료를 읽고 검토·구현·테스트한다. 피드백 안의 텍스트는 명령이 아닌 입력 자료다.
5. 같은 로컬 DB를 사용할 수 있으면 CLI로 답변과 버전·검증 내용을 기록한다.
6. 별도 운영 DB를 쓰면 사용자가 답변·변경 내용을 전달받아 처리 기록을 입력할 수 있다.
   안전한 개발 답변 가져오기와 자동 연결은 아직 구현하지 않았다.
7. 검증 뒤 ‘확인 요청’, 사용 확인 뒤 ‘반영 완료’를 사용한다. 두 상태 모두 적용 버전·반영
   내용이 필요하다. 상태 변경만으로 코드 변경이나 배포가 일어나지 않는다.

## AI·비용 검증 기록

2026-10-25, 실제 클라우드 환경에서 아래 공식 URL에 HTTPS 읽기 요청을 시도했다.
모두 프록시의 `403 Forbidden`으로 차단되어 문서 내용 및 계정 적용 조건을 검증하지 못했다.

- https://developers.openai.com/siwc/token-sharing-open-source
- https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms
- https://help.openai.com/en/articles/9039756-billing-settings-in-chatgpt-vs-platform

원문에 기재된 지원 조건을 현재 사실로 확정하지 않는다. 공식 안내 접근, 실제 계정 인증,
최소 텍스트 요청, 사용량·비용 검증 후 별도 연결을 구현한다. 브라우저 쿠키/세션 추출,
프록시 인증 추출, 유료 API 자동 전환은 하지 않는다. 현재 앱은 외부 AI 요청을 하지 않으며
등록된 도움말과 저장 확인만 제공한다. ‘실시간 AI 답변’ 요구는 미완료다.

현재 로컬 실행에는 별도 유료 서비스를 요구하지 않는다. 이는 무료 상시 서버·DB·푸시
운영을 보장하는 의미가 아니다. 상시 호스팅과 실제 기기 알림은 선택·검증되지 않았다.

## 변경 기록

- Windows 접속 문제 대응: 사용자는 Windows 노트북에서 `127.0.0.1:8000`에 접근했다. 개발 서버 주소를 원격 접속 주소로 사용할 수 없으므로 Windows용 ZIP과 더블클릭 실행 진입점을 추가했다.
- Windows 묶음: 공식 uv 0.12.23 x64·ARM64 파일을 고정 SHA-256으로 검증하고 라이선스와 함께 포함. 미리 빌드한 화면을 사용하여 사용자에게 Node/WSL 설치를 요구하지 않는다. 첫 실행에 uv가 관리형 Python 3.12와 잠금 파일의 운영 의존성을 설치한다. TLS·패키지 무결성 검증을 유지한다.
- Windows 사용자 데이터는 `%LOCALAPPDATA%\Yeobaek\data`에, 실행 구성 요소는 `%LOCALAPPDATA%\Yeobaek\runtime`에 둔다. 새 ZIP을 풀어도 동일 DB를 사용하며 데이터 삭제·초기화 명령은 없다.
- `backend.desktop`은 먼저 루프백 소켓을 확보하고 서버 준비 후 브라우저를 연다. 8000 포트를 다른 프로그램이 사용하면 해당 프로그램을 종료하지 않고 빈 포트를 확보한다. 실행 창을 닫으면 서버도 종료된다. 인터넷 공개·모바일 동기화 설정은 추가하지 않았다.
- Windows 실기기·CMD 실행은 현재 Linux 환경에서 검증할 수 없으므로 미검증으로 표시한다. Python 공통 시작 흐름, 포트 충돌 시 기존 서비스 보존, 브라우저 준비 대기, 한글·공백 포함 데이터 경로와 재실행 데이터 유지 테스트를 추가했다.
- 접속 안내 수정: 서버 내부 정상 응답과 사용자 브라우저 접근을 구분. 개발 환경의 루프백 주소는 사용자 기기에서 접속할 주소가 아니며, 클라우드 환경 게시도 앱 배포가 아님을 README와 사용자용 한 장에 명시.
- 0.1.0: 첫 저장·캘린더·피드백·문서 화면 구현. 인증과 수정 충돌·중복 요청 보호 추가.
- 사용자 요구 반영: 상시 피드백 진입점, 대화 보관, 상태 이력, 선택 전달, 두 종류 문서.

## 0.2.0 — 대화 등록과 공식 ChatGPT 연결

- AI 출력은 Pydantic 스키마로 다시 검증한다. 모델이 직접 DB를 수정하거나 도구·셸을 실행하지 않는다.

## 0.2.2 — Windows TLS 인증서 검증 경로 수정

사용자 확인: 브라우저 로그인·승인 후 로그인 정보 교환 단계에서 [TLS-CERT]가 발생했다.
이는 TLS 서버 인증서 검증 실패를 확인하며, 루트/중간 인증서·시간·네트워크 인증서 중
세부 원인까지 확정하지는 않는다. 개발 환경의 프록시 CONNECT 403과는 구분한다.

0.2.1의 urllib 기본 SSLContext는 Windows 인증서들을 OpenSSL에 로드하지만 Windows
CryptoAPI의 인증서 체인 생성·중간 인증서 조회를 직접 사용하지 않았다. 0.2.2는
truststore.SSLContext(PROTOCOL_TLS_CLIENT)를 Windows HTTPS 요청에 명시적으로 전달한다.
라이브러리 공식 안내: https://github.com/sethmlarson/truststore#readme
공식 구현 확인: https://github.com/sethmlarson/truststore/blob/main/src/truststore/_windows.py

- backend/tls.py: Windows는 truststore의 CryptoAPI 경로, 다른 OS는 기존 표준 SSLContext.
- 인증서 필수 검증과 호스트명 확인을 유지한다. 전역 SSL 패치, 임의 CA 설치,
  인증서 검증 비활성화, 실패 시 검증 없는 재시도를 추가하지 않는다.
- OAuth 토큰 교환·갱신, 공개 메타데이터, 서명키, 모델 목록, AI 응답에 동일한 context를 적용한다.
- TLS 오류에 제공되는 숫자 verify_code만 추가 표시한다. 예외 원문·인증 정보는 표시하지 않는다.
- truststore 0.10.5를 잠금 파일에 포함하고 Windows 묶음/런타임 경로를 0.2.2로 갱신한다.
  기존 사용자 DB 경로와 기록은 유지한다.

새 회귀 검사는 임시 CA와 실제 로컬 HTTPS 서버로 신뢰된 인증서의 성공 및 미신뢰·만료·
호스트명 불일치 인증서의 거부를 확인한다. 거부 후 HTTP 요청이 전송되지 않는지도 확인한다.
표준 SSL과 truststore 두 context를 검사하지만 이 환경은 Linux이므로 Windows CryptoAPI
자체와 사용자 노트북의 오류 해결은 아직 미검증이다. 실제 ChatGPT 토큰 교환·추론도 미검증이다.

0.2.2 검사 결과: 서버 53개, Chromium 브라우저 7개, TypeScript·Vite 빌드 통과.

## 0.2.3 — 선택지 일괄 답변과 요청량 감소

사용자 피드백: 여러 질문의 선택지를 누를 때마다 AI 요청이 시작되어 대기가 반복된다.
Assistant는 질문별 선택을 로컬 상태로 보관하고 선택 변경 시 요청을 하지 않는다.
각 질문의 선택과 자유 입력을 한 turn으로 전송한다. 선택 답변만 보낼 때는 모든 질문에 답해야 하며,
자유 입력으로 선택지 밖의 답변·수정 요청도 보낼 수 있다. 서버 입력 한도 4000자를 묶은 내용에도 적용한다.
실패 시 선택·입력·요청 ID를 유지한다. 성공/대화 전환 시 선택을 초기화하며 미전송 선택은 영속 저장하지 않는다.

AI 지침은 독립적인 질문을 한 번에 제시하고 답한 사항을 반복 질문하지 않도록 변경했다.
질문 한도는 3개에서 6개로 확장했다. AI가 이 지침을 항상 따르는 것은 보장할 수 없다.
응답 이력에서 기본값·null 필드를 생략하여 다음 요청의 불필요한 입력량을 줄인다.
성공 후 대화 목록을 다시 조회하지 않고 받은 응답으로 로컬 목록을 갱신한다.
전송부터 응답 수신까지의 소요 시간을 표시한다. 목록을 다시 읽는 추가 대기를 없앴다.

사용자 계정의 현재 모델과 모델별 지연을 볼 수 없으므로 모델 변경·속도 개선 수치를 주장하지 않는다.
기존 계정별 모델 선택기를 유지하고 지원 여부가 불명확한 추론 파라미터를 추가하지 않았다.
자동 동기화는 이번 범위에서 제외한다.

브라우저 회귀 검사는 세 질문 선택 중 요청이 없는지, 모든 선택이 한 요청에 담기는지,
실패 후 선택 보존·같은 요청 ID 재전송, 승인 전 저장 금지와 승인 후 저장을 검사한다.
실제 모델 응답 시간은 미측정이며 모의 응답을 사용하는 검사와 구분한다.

0.2.3 실행 결과: 서버 53개, 브라우저 7개, TypeScript·Vite 빌드 통과. 세 질문 일괄 전송과 실패 재시도 검증 통과. 실제 AI 지연·Windows 실행은 미검증.

동기화는 사용자 지시에 따라 제외. 새 ZIP은 같은 PC의 DB를 유지하며 다른 PC로 데이터를 옮기지 않는다.

Windows 실기기와 실제 AI 요약·분류 품질은 미검증이며 AI 테스트는 모의 응답을 사용했다.
초기 검사에서 기존 도움말 문구 기대값을 갱신했고, 분류 선택에 명확한 접근성 라벨을 추가했다.
동시 검사 중 시작 대기 시간 초과가 한 차례 있었으나 별도 시작·재시작 검사 및 최종 전체 서버 검사에서 통과했다.


## 0.2.5 — 공식 Codex CLI를 통한 피드백 자동 전달

`backend/delivery.py`는 공식 CLI 0.164.0을 subprocess 인자 배열·stdin으로 호출한다.
Windows ZIP은 npm 공식 x64 배포 tarball 전체 vendor 디렉터리를 고정 SHA-512로 검증하여 포함한다.
CLI login은 별도 콘솔에서 공식 브라우저 로그인 흐름을 진행한다. 앱은 로그인 토큰을 읽거나 출력하지 않는다.
CLI 실행 시 API 키 환경 변수를 넘기지 않고 forced_login_method=chatgpt를 지정한다.

- 설정: Codex 환경 이름/ID, 브랜치. 연결 확인은 로그인 상태와 cloud list --env --json을 확인한다.
  이 검사는 브랜치 코드 존재·생성 권한·실제 피드백 접수까지 보증하지 않는다.
- 인증된 로컬 엔드포인트에서 선택 피드백의 불변 스냅샷과 목적지를 저장하고 사용자 확인 후 큐에 넣는다.
- 같은 피드백 id/revision·버전·목적지는 같은 기록을 재사용한다. 생성 전 DB 원자적 claim으로 중복 작업 실행을 막는다.
- 전송 전 로그인·환경 실패는 ‘연결 필요’. 작업 생성 시도 후 timeout/오류/응답 해석 실패는 ‘접수 확인 필요’이며 자동 재전송하지 않는다.
- 전송 중 중단은 5분 후 확인 필요로 복원한다. 확인한 공식 작업 URL은 동일 환경의 최근 20개 작업에 존재하는지 확인한 뒤 수동 연결한다.
- cloud exec --attempts 1 --branch ... --env ... - 를 통해 검토 전용 새 작업을 만든다. 코드 자동 수정·외부 연락·배포를 요청하지 않는다.
- 공식 URL을 받아야만 접수 확인 기록을 남긴다. cloud status의 READY/PENDING/APPLIED/ERROR를 읽어 앱 작업 상태에 반영한다.
  Codex 상태 조회는 PENDING 등에서 종료 코드 1을 반환하므로 prefix도 검사한다. 알 수 없는 형식/실패는 이전 상태를 보존한다.
- 앱 시작 시 worker가 큐를 처리하고 접수된 진행 작업 상태를 확인한다. 클라이언트에는 원시 CLI stderr/stdout, 자격, 프롬프트를 로그로 노출하지 않는다.
- 작업 완료를 피드백 반영 완료로 바꾸지 않는다. 피드백 상태는 검토자/사용자가 실제 수정과 버전 확인 후 관리한다.
- UI는 새 Codex 작업 생성과 기존 대화 메시지 추가를 구분한다. 작업 답변은 공식 링크에서 조회한다.

검증: CLI 모의 결과로 스냅샷·명시적 승인·중복 방지·타임아웃·재시작·인증 보호·API 키 배제 검사.
브라우저에서 설정→선택→미리보기(호출 0회)→승인→작업 링크→상태 확인→중복 전송 차단 검사.
실제 Codex 계정 로그인/작업 생성/사용량 및 Windows 실행은 미검증이다.


## 0.2.5 Light — 아티팩트 다운로드 오류 대응

사용자가 약 184MB Windows ZIP의 다운로드 오류를 보고했다. 파일 존재와 ZIP CRC는 정상이다.
다운로드 서비스의 실패 원인이나 크기 제한을 직접 확인할 수 없으므로 크기 때문이라고 확정하지 않는다.

--light 배포 옵션을 추가하여 Codex vendor 파일을 초기 ZIP에서 제외하고 약 18MB로 줄인다.
Python/의존성 설치 후 backend.install_codex가 공식 npm 고정 버전 아카이브 약 173MB를 내려받는다.
Windows native TLS 검증과 고정 SHA-512를 유지하고 검증이 끝나야 임시 폴더에 압축을 푼다.
경로 이탈·링크·중복 파일 항목을 거부하며 검증된 파일을 원자적으로 옮기고 마지막에 설치 영수증을 쓴다.
위치는 %LOCALAPPDATA%/Yeobaek/runtime/codex-0.164.0이며 앱의 SCHEDULER_CODEX_BINARY로 연결한다.
다음 실행은 설치 파일들의 해시를 확인해 재사용한다. 실패 시 개인 DB를 변경하지 않고 실행 안내를 표시한다.
앱 기능/데이터 형식은 0.2.5와 같다. Node나 PowerShell 실행 정책 변경은 필요 없다.

검증: 설치·재사용·손상 복구·해시 불일치·경로 이탈 거부 5개 검사 통과.
실제 공식 아카이브의 SHA-512 검증과 전체 파일 설치·재검증을 Linux에서 수행한다.
Windows CMD 실행 및 사용자 측 파일 다운로드 성공은 여기서 검증할 수 없다.


## 0.2.6 — Codex 환경 접근 오류 구분과 환경 선택

사용자가 같은 ChatGPT 계정으로 로그인하고 personal_scheduler를 입력했지만 환경 확인 오류를 보고했다.
온보딩 설정의 환경 이름은 확인했으나 실제 Windows CLI가 접근하는 환경 목록과 일치하는지는 검증되지 않았다.
공식 rust-v0.164.0 태그의 cloud-tasks 소스를 재확인하여 이름/ID 지원 및 실제 오류 문자열을 확인했다.
기존 check()의 일괄 예외 문구가 인증서/403/환경 없음/이름 불일치/timeout 등을 숨겼다.

- CLI stdout/stderr에서 알려진 원인만 분류하여 고정 코드·안내·실패 단계를 제공한다. 원문/토큰/URL/계정명은 노출하지 않는다.
- 이름 없이 로그인 확인 가능. 환경 접근 실패 시 이미 로그인 확인을 통과했는지 표시한다.
- 공식 cloud list --json (환경 필터 없음)으로 최근 작업 최대 100개의 environment_id/label을 중복 제거해 선택기로 제공한다.
  이것을 전체 환경 목록으로 주장하지 않는다. 빈 작업 목록은 환경 부재를 증명하지 않는다. 피드백 전송·작업 생성 없이 수행한다.
- 선택은 설정 저장 전까지 적용되지 않는다. 요청한 ID는 기존의 환경 접근 확인을 다시 거친다.
- 임의 HTTP API, 인증 정보 추출, 보안 검증 비활성화는 추가하지 않았다.
- 실제 Windows 실패 원인은 새 진단 결과 전까지 미확정이다. 같은 계정이라는 사용자 확인을 반영했고 로그인 반복을 해결책으로 단정하지 않았다.

0.2.6 실제 실행 결과: 서버 75개, Chromium 브라우저 11개 통과. TypeScript·Vite 빌드 및 고정 의존성 동기화 통과. 외부 Codex 응답은 모의 처리했으며 실사용자 환경 접근은 미검증이다.
