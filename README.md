# 여백 — 개인 생활 비서

일정과 날짜 없는 할 일을 저장하고, 사용 중 남긴 질문·오류·기능 제안을 개선 기록으로 관리하는 개인용 웹 앱입니다.
0.2.0에는 공식 ChatGPT 로그인과 대화→선택지→승인 등록 코드를 추가했습니다. 실제 계정 연결과 추론은 사용자 로그인 후 검증해야 합니다. 푸시·상시 배포는 아직 미지원입니다.

0.2.2는 Windows 기본 인증서 검증 기능을 직접 사용하도록 수정했습니다. 로그인 후 `[TLS-CERT]` 오류에 대응한 변경이며 실제 노트북에서 재확인이 필요합니다. **인증 서버 연결 확인**과 실패 단계·원인 코드 안내도 유지합니다.

0.2.3에서는 여러 질문의 선택과 추가 설명을 한 번에 보냅니다. 선택 중에는 AI 요청을 보내지 않으며 답변 소요 시간을 표시합니다.

## 대화로 등록 (0.2.0부터)

앱 로그인 → **대화로 등록 → Continue with ChatGPT** → 구독 사용 권한 확인 →
**사용 가능한 모델 불러오기** → 모델 선택 → 대화 입력 → 선택지 답변 → **확인한 내용 등록**.
승인 전에는 실제 일정이 추가되지 않습니다. 같은 버튼을 다시 눌러도 중복 등록하지 않습니다.
사용자 계정의 구독/앱 한도가 적용되며 크레딧 사용 허용 여부는 ChatGPT 설정에서 확인하세요.
유료 API 키나 비공개 ChatGPT endpoint는 사용하지 않습니다.

현재 개발 환경은 auth.openai.com 접근이 차단되어 실제 로그인을 검증하지 못했습니다.
연결이 거부되면 오류를 알려주세요. 연결·모델·실제 응답 성공을 미리 보장하지 않습니다.
AI 인증 정보가 로컬 데이터 파일에 포함되므로 데이터 파일은 공유하지 마세요.

## Windows에서 간단히 실행하기

Windows용 ZIP의 **전체 압축을 푼 뒤 `START-Yeobaek.cmd`를 더블클릭**하세요.
첫 실행 시 인터넷으로 Python과 앱 구성 요소를 준비하고, 서버가 준비되면 브라우저가 열립니다.
Node.js·WSL·관리자 권한은 필요하지 않습니다. 사용하는 동안 실행 창을 열어 두세요.
브라우저가 자동으로 열리지 않으면 실행 창에 표시된 주소를 입력하세요. 기본 포트 8000이
사용 중이면 다른 빈 포트를 사용합니다. 프로그램 실행 없이 주소만 입력해서는 열리지 않습니다.

데이터는 `%LOCALAPPDATA%\Yeobaek\data\scheduler.sqlite3`에 저장합니다. 업데이트할 때
기존 실행 창을 닫고 새 ZIP을 다른 폴더에 풀어 실행하면 같은 데이터를 사용합니다.
압축을 푼 프로그램 폴더를 지워도 사용자 데이터 폴더는 남습니다.
Intel/AMD x64 Windows 10/11용입니다. ARM64 Windows 11은 x64 호환 실행을 사용하며 ARM64 Windows 10은 지원하지 않습니다. **실제 Windows 기기에서의 실행은 미검증**이며,
현재는 Linux에서 시작 절차·브라우저 준비 대기·포트 충돌·재시작 저장을 검증했습니다.

이 방식은 노트북에서만 접속하는 개인용 실행입니다. 휴대폰 접속이나 인터넷 배포가 아닙니다.
오류가 나면 실행 창이 유지되므로 오류 문구를 알려주세요. 보안 프로그램을 끄거나 관리자
권한으로 실행하지 말고, 차단된 경우 그 메시지를 확인해 주세요.

개발자가 Windows 묶음을 다시 만들 때:

```bash
npm run build
python3 scripts/package_windows.py /workspace/artifacts/Yeobaek-Windows.zip
```

공식 uv 0.12.23 Windows 바이너리를 고정 SHA-256으로 검증해 묶습니다. 화면 빌드와 원본 앱,
잠금 파일, 문서를 포함하고 실제 사용자 데이터·비밀번호·개발 환경 파일은 제외합니다.

## 개발 환경에서 시작하기

**현재 클라우드에서 실행 중인 앱에 사용자 브라우저로 접속할 공개 주소는 아직 없습니다.**
`127.0.0.1`은 브라우저를 연 기기 자신을 가리킵니다. 사용자 노트북에서 앱을 실행하지 않은 채
이 주소를 입력하면 클라우드 앱에 연결되지 않습니다. Codex 환경을 게시하는 것도 앱의 웹 배포와는 별개입니다.
아래 명령은 개발 환경 또는 앱 소스와 도구를 준비한 컴퓨터에서 실행하는 절차입니다.

Python 3.12 이상, Node.js 22 이상, [uv](https://docs.astral.sh/uv/)가 필요합니다.

```bash
cd /workspace/personal_scheduler
uv sync --frozen
npm ci
npm run build
bash scripts/start.sh
```

앱은 명령을 실행한 컴퓨터의 포트 8000에서 실행됩니다. **그 컴퓨터에서** 브라우저 주소창에 `127.0.0.1:8000`을 입력하세요.
처음 열 때 본인만 사용할 12자 이상의 비밀번호를 만듭니다. 공개 회원가입은 없습니다.
클라우드 작업 환경의 루프백 주소는 사용자 휴대폰에서 접근할 주소가 아닙니다.
일반 PC에서는 저장소 디렉터리로 이동한 뒤 같은 명령을 실행하세요. 아래 Bash 개발 명령은 Windows의 WSL에서도 사용할 수 있습니다. 위 Windows 실행 묶음에는 WSL이 필요하지 않습니다.

개발 중 화면 자동 갱신이 필요하면 두 터미널에서 실행합니다.

```bash
# 터미널 1
.venv/bin/python -m uvicorn backend.asgi:app --host 127.0.0.1 --port 8000 --no-proxy-headers --no-access-log
# 터미널 2
npm run dev
```

## 피드백과 문서

어느 화면에서든 ‘질문 · 피드백’을 열 수 있습니다. 대화는 저장되고 ‘개선 기록’에서 이어집니다.
앱 사용 안내는 정적 도움말이며 실제 AI 답변이 아닙니다. 필요한 의견을 선택하여 전달 내용을
확인한 다음 JSON 파일을 내려받아 Codex 대화에 첨부합니다. 일정 내용은 자동 첨부하지 않습니다.

- [사용자용 한 장](docs/USER_OVERVIEW.md): 목표, 가능한 기능, 완료 기준, 다음 단계.
- [개발용 상세 기록](docs/DEVELOPMENT.md): 구조, 검증, 제약, 판단 이유.
- [원본 요구사항](docs/ORIGINAL_REQUIREMENTS.md): 장기 목표와 요구.

두 관리 문서는 앱의 ‘개발 현황’에서도 읽고 내려받을 수 있습니다. 기능 변경 시 함께 갱신합니다.

개발자가 같은 DB에 접근할 때:

```bash
.venv/bin/python -m backend.feedback list
.venv/bin/python -m backend.feedback reply THREAD_ID --file /path/to/reply.txt
.venv/bin/python -m backend.feedback status THREAD_ID --status '확인 요청' --version 0.1.1 --file /path/to/change-note.txt
```

개발 기록을 남기는 도구이며 AI나 코드를 자동 실행하지 않습니다. 별도 운영 서버의 대화가
이 작업 환경으로 자동 전송되거나 설치된 앱이 자동 업데이트되지는 않습니다.

## 데이터와 백업

기본 DB는 `.data/scheduler.sqlite3`입니다. `SCHEDULER_DB` 환경 변수로 별도 경로를 지정할 수 있습니다.
앱 재시작 후에도 같은 파일을 사용하면 데이터가 유지됩니다. DB·백업에는 개인정보와 인증 해시가
포함되므로 Git이나 피드백 전달 파일에 넣지 마세요.

```bash
# SQLite의 일관된 백업 API 사용. 원본을 그대로 복사하는 중간 상태를 피합니다.
.venv/bin/python -m backend.feedback backup /안전한/경로/scheduler-backup.sqlite3
```

복원할 때는 서버를 종료하고 현재 DB를 별도로 보관한 다음 백업을 DB 경로로 복사하고
파일 권한을 본인만 읽고 쓸 수 있게 설정합니다. 먼저 별도 `SCHEDULER_DB` 경로에서 복원을
검증하세요. 비밀번호도 함께 복원됩니다. 백업은 SQLite `integrity_check` 검사를 거칩니다.

## 휴대폰·인터넷 접근

현재 스크립트는 루프백 전용입니다. 개인용 상시 호스팅은 아직 선택·배포하지 않았습니다.
외부 접근이 필요하면 먼저 로컬에서 비밀번호를 설정하고, HTTPS reverse proxy와
`SCHEDULER_ORIGIN=https://본인의호스트`를 구성해야 합니다. 호스트·Origin이 일치해야 요청이
허용되며 HTTPS 설정에서 Secure 쿠키가 사용됩니다. 프록시 뒤 최초 설정 노출을 피하세요.
원격 접속에는 보안·가용성·비용 검증이 추가로 필요합니다.

같은 서버에 접속하면 15초 간격과 화면 복귀 시 최신 상태를 읽습니다. 서로 오래된 내용을
수정하면 충돌을 알립니다. 실제 휴대폰 동기화·푸시 수신은 검증되지 않았습니다.
현재 앱은 푸시나 예약 알림을 보내지 않습니다. 노트북에서 실행하면 노트북 종료 시 앱도 중단됩니다.
